# Companion note · the GBP post workflow

> Explains **[`docs-template/gbp_posts.md`](../docs-template/gbp_posts.md)** — a queue of
> ready-to-publish Google Business Profile posts plus a log of what's gone out. Copy it
> (with the rest of `docs-template/`) into your project as `docs/gbp_posts.md`.

This note is background, not a file you copy.

## Why it's a queue, not an integration

No GBP API wiring. Posting is manual: copy the text into GBP → Posts → Update, set the
CTA button and link, attach a real photo, publish, then move the entry from **Queue** to
**Posted** with the date. For a one- or two-person business, a weekly copy-paste is less
to maintain and less to break than an integration.

## The rule for every post

**It ties to something real** — a blog post you published, a genuine operational change,
a seasonal angle with a real recommendation, a real before/after photo. Never a
fabricated claim, never stock-photo filler. Photo posts with a real crew/job shot get
meaningfully more views than text-only.

## What the file holds

Three or so queued posts, each with its body text, the exact CTA + link, the kind of
photo to attach, a rough character count, and what it's tied to. Then a **Posted** table
so nothing gets reused too soon.

## Cadence

Weekly. If there's nothing real to post about this week, skip it — an empty week beats a
filler post.
